# M4: edge induction and message passing

Goal: give the latent nodes a *graph*, learned from the text alone, and let a few message-passing
layers move information along it so that multi-hop relations end up inside the node vectors (H1,
H3). No parser and no entity extraction is used anywhere.

## Edge induction (`model/edges.py`)

For relation `p` (`R = 4` relations) the score of "node `i` reads from node `j`" is a low-rank
bilinear form with a learned relation embedding:

```
s_p(i, j) = (U z_i)^T diag(w_p) (V z_j) / sqrt(r)          U, V: d -> r (r = 64),  w_p in R^r
```

Each node `i` chooses what to read from over **all** `(relation, node)` pairs at once, plus a learned
"no edge" option `n_i = b^T z_i`:

```
a_i = entmax_1.5( [ s_p(i, j) for all p, j != i ,  n_i ] )      # entries for padded/closed nodes: -1e4
A[p, i, j] = a_i[(p, j)]                                         # the "no edge" entry is dropped
```

so row sums of `A` are at most 1, and a node can choose to read from nothing. The result is
`A in R^{R x K x K}` (a batch dimension aside).

**Why entmax and not softmax.** Softmax gives every pair a positive weight, so there is no graph, only
a dense mixing matrix. Entmax with alpha = 1.5 (Peters et al., 2019) returns a probability vector
with *exact zeros*. It is implemented here with the sort-based exact solution using ordinary
differentiable tensor operations, and checked against a bisection reference. After entmax, each row
keeps at most `max_deg` (8) entries (see the next paragraph).

**Degree cap, and a bug found by running it.** The cap keeps the `max_deg` largest entries of a row
and rescales them to the row's original total. The first version selected entries with a value
threshold (`weights >= kth`). In a smoke run on real inputs the mean degree came out at 8.9 for a
cap of 8. The cause was that under bf16 autocast the scores were low precision, many tied, and the
threshold kept every tied entry. Two fixes: edge induction now ignores autocast and runs in float32
(entmax's sort and cumulative sums also need the precision), and the cap selects exactly `max_deg`
entries by index, so ties cannot exceed it. Both are tested.

**Gumbel top-k ablation.** `edges.sparsifier: gumbel_topk` instead picks `max_deg` entries per node
from Gumbel-perturbed logits (training only) and weights them by a softmax of their clean logits.
The indices are not differentiable but the weights are, so gradients still reach the scores.

**The edge penalty is a soft one.** The original plan mentioned hard-concrete gates on edges. A gate
per candidate edge would need `R * K^2` gates (millions per document), so sparsity here comes from
entmax's exact zeros, the "no edge" option and the degree cap. The only edge penalty
(`loss.edge_l0`, 0.01) is on `sum_i (1 - p_no_edge_i) / N`, the soft number of nodes that read from
anything. It discourages needless connectivity but does not count edges one by one, so it is
named `edge_l0` loosely.

## Message passing (`model/gnn.py`)

Per layer (2 layers), with pre-LayerNorm and residuals:

```
m_i = sum_p sum_j A[p, i, j] * W_p LN(z_j)
z_i <- z_i + O m_i
z_i <- z_i + FFN(LN(z_i))
```

After `L` layers a node depends on its `L`-hop neighbourhood, which is how a relation such as "the
director of X, and that person's mother" can end up in one node. Nothing in the layer uses a node's
index, so it is **permutation-equivariant**: permute the nodes and the adjacency consistently and the
outputs permute the same way (tested, as is the edge inducer alone). A chain test checks that two
layers carry information two hops and one layer does not.

`O` starts at zero, so training begins from the routed model and the graph pathway grows in as it
becomes useful. A consequence is that the edge parameters get no gradient at step 0 and only start
learning once `O` has moved. The tests randomise `O` before checking gradient flow.

## Graph positional bias (`model/projector.py`, `edges.rw_positional_encoding`)

The LLM needs to know where in the graph each vector sits. For each node the encoding is the vector
of random-walk *return probabilities* `[ (A_sum^t)_{ii} for t = 1..8 ]`, where `A_sum` is the
adjacency summed over relations. It describes the node's local structure (cycles, hubs) without
using its index, so it is also permutation-equivariant, and it is computed without gradient. A linear
layer adds it to the node state before the projector.

## Structural controls (the point of H1)

`type: graph` with switches:

| `name` | edges | message passing | what it tests |
|---|---|---|---|
| `graph` | learned | on | the full model |
| `graph_noedges` | off | on, empty messages | same parameters, no structure |
| `graph_random` | random, equal degree and relations | on | structure with no content |
| `routed_adaptive` (M3) | none | none | the node set alone |
| `flat` (M2) | none | dense slot attention | strong Perceiver-style baseline |

If `graph` does not beat `graph_noedges` and `graph_random`, an improvement over `routed_adaptive`
cannot be credited to structure.

## Watching for edge collapse

The main risk is that the model ignores `A`, so that the "graph" is flat slots with extra steps. The
training log records `mean_degree`, `edge_entropy` (entropy of each node's read distribution),
`edge_mass` (row sums) and `active` (open nodes). Constant degree, a near-uniform entropy or
`edge_mass` falling to 0 would signal collapse. M5 adds a probe that asks whether the edges mean
anything.

## Cost

`A` has `B * R * K^2` entries. At ratio 2 with the adaptive pool the largest `K` is about 1150, so
the edge module is the memory-hungry part, and the random-walk powers cost `K^3` per step. The edge
and positional computations are therefore the first things to shrink (`edges.rank`,
`projector.pe_steps`, `data.max_ctx_tokens`) on a small GPU.

## Tests

Entmax: sums to one, agrees with a bisection reference, has exact zeros, is shift invariant and
batched, finite gradients, ignores masked entries. Degree cap: exactly `max_deg` kept even with ties
and the total mass preserved. Edges: no self loops, nothing on padding, row sums at most one,
degree at most `max_deg`, exact sparsity, gradients to every parameter for both sparsifiers,
permutation equivariance, dependence on content, float32 output under autocast. Message passing:
equivariance, padding independence, zero on invalid nodes, two-hop reach. Positional encoding: a
2-cycle with known return probabilities, equivariance. Random graph: degree and masks. Compressors:
the four switch combinations, gradients to edge and message parameters, closed nodes excluded from
the graph.
