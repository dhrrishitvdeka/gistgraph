# M1: evaluation harness and non-learned baselines

Goal: a trustworthy way to score any context-compression method, plus the baselines that need no
training. Every later milestone reuses this harness, so the comparison rules are fixed here.

## The task and the prompt

Each example is a question with a long context. The frozen LLM (`Qwen/Qwen2.5-0.5B-Instruct`)
reads the context and answers. The prompt is rendered once with the model's chat template and a
placeholder where the context goes (`data/prompts.py`), then split into `pre` and `post` text:

```
pre  + [ context text  |  soft-prompt embeddings ] + post
```

A text method fills the slot with text. A learned compressor fills it with embeddings. The words
around the slot are identical in both cases, so the only thing that differs is the context
representation. Decoding is plain greedy (`repetition_penalty=1.0`, which overrides Qwen's default
of 1.05), at most 32 new tokens, and only the first line of the output is scored.

## Data

| name | source | role |
|---|---|---|
| `hotpotqa` | HotpotQA distractor, multi-hop | train and eval |
| `2wiki` | 2WikiMultihopQA, multi-hop | train and eval |
| `squad` | SQuAD v1.1, single-hop | train and eval |
| `longbench_*` | LongBench `hotpotqa`, `2wikimqa`, `musique` | eval only |

The loaders parse each dataset into one `Example` (`context`, `question`, `answers`, the context's
paragraphs, which paragraphs hold supporting facts, and the number of hops). Parsing is separated
from downloading, so the parsers are unit tested offline. LongBench is read from its raw zip,
because the Hugging Face loader for it relies on a dataset script that `datasets` no longer runs.

Subsets are seeded random samples (`data.n_eval`, default 500; the runs reported here use 200
because of compute). Every method, including the full-context reference, sees the context cut to
its first `data.max_ctx_tokens` (1536) tokens. This keeps comparisons fair, but it means a LongBench
context is usually cut, which can remove the answer for every method alike.

## Metrics

- **EM / F1**: the official SQuAD recipe (lowercase, strip punctuation and articles) and the best
  score over all gold answers.
- **Achieved ratio** `n_orig / n_comp`, counted in the frozen LLM's tokens. For a learned model
  `n_comp` is the number of soft-prompt vectors.
- **Retention** = `mean F1 of the method / mean F1 of the full context` on the same examples. It is
  a ratio of means. A mean of per-example ratios would be unstable, since the full-context F1 of
  many examples is 0.

Methods are compared at the ratio they *achieved*. A method that asks for 4x but delivers 5x has
not been compared fairly with one that delivered 4x.

## Baselines (`baselines/`)

All take `(example, ratio, tokenizer)` and return a shorter text with `floor(N / ratio)` tokens.

- **Truncation**: keep the first tokens (`truncation_head`) or half from each end
  (`truncation_headtail`, the common LongBench practice).
- **Extractive**: split into sentences, score them, keep the best ones that fit the budget, and
  output them in original order. Scores: `lead` (earliest first), `textrank` (centrality in a
  TF-IDF cosine graph, query-agnostic), `bm25` (Okapi BM25 against the question, **query-aware**).
  Whole sentences rarely fill the budget exactly, so the leftover budget is filled with a cut of
  the next-best sentence. Without this the extractive baselines overshot (4.7x achieved for a 4x
  target), which understated them.
- **LLMLingua-2**: the `llmlingua` package (token classification by a small encoder). It takes a
  rate in *its own* tokenizer's units, so its achieved ratio in Qwen tokens differs a little from
  the request, and the harness reports the achieved value.

`query_aware` is a property of every baseline. The learned compressors never see the question, so
query-aware methods are a different, easier setting and are labelled as such in the tables.

## Harness (`eval/`)

`run_eval(lm, examples, prepare, ...)` takes a callback that turns an example into either a text
context or a soft prefix, builds the prompts, generates in batches (sorted by length to reduce
padding), and returns one scored row per example. Learned methods in M2-M5 use the same function,
so a result row means the same thing for every method. `aggregate`, `retention_table` and the
Markdown tables work on those rows. `run_baselines` is resumable: it skips any
(method, ratio, dataset) already present in `results.jsonl`.

## Tests

SQuAD normalisation and F1 on hand-computed cases (including repeated tokens); each baseline's
token budget, ordering and query awareness; the dataset parsers on synthetic records; the prompt
split; the soft-prefix placement and gradient flow in `FrozenLM`; batching not changing
predictions; aggregation, retention and the report tables.

## Reproduce

```bash
python -m gistgraph reproduce m1            # all datasets, all baselines, all ratios
python -m gistgraph baselines --config configs/experiments/m1_baselines.yaml \
    "data.eval=[squad]" "data.n_eval=50"    # a quick check
```

## Partial result (HotpotQA, n = 200, run still in progress)

At the time of writing only HotpotQA had finished, and LLMLingua-2 at 5x had not. Full-context F1
is 30.3 (EM 18.0). F1 retention, with the achieved ratio in brackets:

| method | 2x | 3x | 4x | 5x |
|---|---|---|---|---|
| extractive_bm25 (query-aware) | 102% (2.0x) | 92% (3.0x) | 97% (4.0x) | 89% (5.1x) |
| extractive_lead | 88% | 78% | 78% | 76% |
| extractive_textrank | 73% | 69% | 66% | 63% |
| truncation_head | 86% | 79% | 77% | 71% |
| truncation_headtail | 94% | 75% | 76% | 70% |
| llmlingua2 | 90% (1.9x) | 75% (2.7x) | 55% (3.6x) | - |

The query-aware BM25 baseline is very strong on HotpotQA, because the distractor setting contains
many sentences that share no words with the question. A query-agnostic compressor has to be judged
against that bar with the difference in access in mind. These files live in `runs/` (git-ignored);
rerun the command above to regenerate them.
