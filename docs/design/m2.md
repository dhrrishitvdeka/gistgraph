# M2: flat-slot compressor with distillation

Goal: the baseline learned compressor that the graph model must beat. It is deliberately a strong
version of the common design (a Perceiver or ICAE style bottleneck of flat latent slots), trained
with the same objective, data and budget as every later variant.

## Pipeline

```
context tokens ──frozen LLM, layer 12──▶ features h [N, d_llm]          (no gradient)
h ──SegmentEncoder──▶ segments u [M, d]
u ──FlatSlotWriter──▶ K = floor(N / ratio) slots z [K, d]
z ──Projector──▶ soft prompt e [K, d_llm]  ──▶  frozen LLM reads  pre + e + post
```

**Why use the LLM's own hidden states as input.** A second language model as the encoder would
need to be loaded next to the LLM and would double the memory. A middle layer of the frozen LLM
already holds contextual token features. They are computed once under `no_grad`, so only the small
compressor receives gradients.

## SegmentEncoder (`model/encoder.py`)

LayerNorm and a linear map to width `d` (512), optional mean-pooling of windows of `seg_len` tokens
(masked, so padding does not dilute the mean), fixed sinusoidal position codes, then a 2-layer
pre-LayerNorm transformer encoder with a key-padding mask. Padding content cannot change valid
outputs (tested). `pos_offset` lets a chunk of a longer text keep its absolute positions (used by
streaming in M5).

## FlatSlotWriter (`model/writer.py`)

`k_max` learned query vectors. A learned embedding of `log(ratio)` is added to them, so a single
network serves several ratios. Each of 2 blocks is: slots cross-attend to the segments, slots
self-attend, feed-forward, all pre-LayerNorm with residuals. A document with `N` tokens uses the
first `floor(N / ratio)` queries (at least 1), and unused slots are masked out of the attention and
zeroed. Valid slots do not depend on the unused ones (tested).

This writer lets slots attend to each other, which is a dense, implicit form of interaction. The
routed and graph models in M3-M4 do not have it, which makes the H1 comparison conservative: the
graph model has to beat a flat model that already has dense slot-to-slot attention.

## Projector (`model/projector.py`)

An MLP into the LLM embedding width, then each output vector is L2-normalised and multiplied by a
learned gain that starts at the mean norm of the LLM's token embeddings. A soft prompt with vectors
far larger or smaller than real embeddings is out of distribution for the frozen LLM and is a common
cause of unstable training. The norm calibration removes that failure by construction.

## Objective (`train/losses.py`)

**Distillation.** The teacher is the same frozen LLM reading the *full* context. For every training
example it is run once (`data/teacher_cache.py`), recording its greedy answer `y_1..y_T` (including
the end token) and, at every step, its top-64 logits. Training then minimises, over answer steps,

```
KL( p_teacher^top64 || p_student ) * T^2
p_teacher = softmax(top-k logits / T)  (renormalised over the 64 entries)
log p_student = log_softmax(full-vocabulary logits / T), read at the same 64 indices
```

The student is conditioned on the soft prompt instead of the context. Reading the student at the
teacher's indices, from a softmax over the whole vocabulary, still punishes mass placed outside the
teacher's support. The teacher cache removes the long full-context forward pass from training, which
is the main compute saving on a small GPU.

**Why the teacher's own answers and not the gold answers.** Teacher forcing the gold answer would
teach the student to give the short gold-format answers the teacher itself does not give. Retention
would then be measured against a teacher the student has partly surpassed. Matching the teacher's
distribution on the teacher's own answers keeps "retention" meaning what it says. A gold-answer
cross-entropy term exists (`loss.qa_ce_weight`) and is off in the shipped configs.

**Reconstruction (auxiliary, stabilising).** The LLM must repeat the first `recon_tokens` (48)
tokens of the context from the soft prompt alone. Its weight starts at `recon_weight` and falls
linearly to zero over the first `recon_anneal_frac` (30%) of training. It gives the slots a dense,
easy early signal before the distillation signal is informative. `answer_logits` applies the LM head
only at answer positions, so a `[batch, length, 150k]` logits tensor is never built.

## Training (`train/trainer.py`)

- A target ratio is drawn per micro-batch from `train.ratios` (2, 3, 4, 5), so one model serves all
  ratios (the ratio is also an input).
- AdamW, linear warm-up then cosine decay to 10% of the peak, gradient clipping at 1.
- bf16 autocast where supported, fp16 with a gradient scaler otherwise. The compressor's weights are
  fp32.
- Data order and ratios are a deterministic function of the seed and the step, and a checkpoint
  holds the model, optimiser, scaler and step, so a run interrupted on a free GPU session resumes
  exactly.
- The shared budget for all variants is 1000 optimizer steps of 16 examples on 3000 teacher
  examples (about 5 passes). This is small, and every model is trained the same way.

## Tests

Shapes and masking in the encoder and writer; slot counts per ratio; projector norm; gradients
reaching the writer through the frozen LLM; the answer-aligned inputs and `answer_logits` matching a
full forward pass; the KD loss being zero for identical distributions, ignoring masked positions and
having gradient; the learning-rate and annealing schedules; the teacher cache round trip; training
reducing the loss on a toy problem and resuming from a checkpoint.

## Reproduce

```bash
python -m gistgraph reproduce m2
# or: python -m gistgraph train --config configs/experiments/m2_flat.yaml
```
