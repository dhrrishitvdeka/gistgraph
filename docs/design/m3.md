# M3: routed writing and the rate penalty

Goal: let information-dense text claim more capacity (H2) without fixing the compression ratio in
advance, while still landing on the requested *average* ratio so that results stay comparable.

## Routed writing (`model/routing.py`)

Segments `u_m` write to latent nodes through sparse top-k routing, as in a mixture-of-experts layer.

```
logits[m, k] = (W_r u_m) . key_k / sqrt(d)              key_k = learned vector + ratio embedding
p[m, :]      = softmax over the valid nodes (plus small Gaussian noise while training)
write[m, :]  = top_k entries of p[m, :], renormalised to sum to 1   (exactly top_k nonzeros)
z_raw[k]     = sum_m write[m, k] * (W_v u_m)  /  sum_m write[m, k]
z[k]         = FFN blocks( LayerNorm( z_raw[k] + W_k key_k ) )
```

Every segment therefore touches exactly `top_k` (2) nodes, which is the sparse write that the tests
check on valid and padded segments alike. A node's state is the weighted *mean* of what it received,
so a node that receives more segments is not simply larger.

Nodes do **not** attend to each other here. Any interaction between nodes is added explicitly in M4
as edges and message passing. Keeping it out of the writer is what makes the graph-versus-flat
comparison a controlled one.

**Load balance.** Left alone, a router sends everything to a few nodes. The Switch-Transformer loss
`K * sum_k f_k * P_k` is added, where `f_k` is the fraction of segments whose top choice is node `k`
and `P_k` the mean router probability of node `k`. It equals 1 for a perfectly even router and is
larger for a collapsed one (tested).

**Node order.** The LLM reads the nodes in sequence, so they are sorted by the *centroid* of their
source positions (`sum_m write[m,k] * position_m / sum_m write[m,k]`). Content from the start of the
document stays at the start, which keeps the LLM's position information meaningful.

## Fixed versus adaptive

- `writer.adaptive: false` (`routed_fixed`): exactly `floor(N / ratio)` nodes per document.
- `writer.adaptive: true` (`routed_adaptive`): the candidate pool is `capacity_factor` (1.5) times
  larger, and a **hard-concrete gate** per node decides which stay open. A dense, information-rich
  document can keep more nodes than a repetitive one. The reported compression is the *achieved*
  one, so adaptivity is judged at equal average compression.

Note on `capacity_factor`: in this implementation it sets the size of the candidate pool. It is not
a hard per-node capacity that drops overflowing segments, as in Switch routing. Balance is
encouraged by the loss instead.

## Hard-concrete gates (`model/gates.py`)

Each node has a gate `g in [0, 1]` that is *exactly* 0 or exactly 1 with non-zero probability
(Louizos et al., 2018). With `log_alpha = f(z)`:

```
training:  s = sigmoid((log u - log(1-u) + log_alpha) / beta),  u ~ U(0,1)
           g = clip(s * (zeta - gamma) + gamma, 0, 1)            beta=2/3, gamma=-0.1, zeta=1.1
eval:      g = clip(sigmoid(log_alpha) * (zeta - gamma) + gamma, 0, 1)      (deterministic)
E[open] =  sum_k sigmoid(log_alpha_k - beta * log(-gamma / zeta))            (differentiable)
```

A node is part of the memory when `g > 0`. The expected number of open nodes is differentiable, so
a penalty on it trains `log_alpha`. The tests check that this formula agrees with a Monte Carlo
estimate of `P(g > 0)`. The gate bias starts at +2, so every node begins nearly open and the model
is not forced to throw information away before it has learned to use it. A document is never left
with an empty memory: its best node is reopened.

Closed nodes contribute nothing: their vectors are zeroed in training, and in the soft prompt they
are removed entirely, so the LLM sees only the open nodes.

## Rate control (`train/rate.py`)

The constraint is that the average open fraction of nodes equals `1 / ratio`. With
`g = open_fraction - 1/ratio` (the mean over the batch), the loss gets

```
lambda_r * g  +  (rho / 2) * g^2          lambda_r += eta * g   after every batch
```

with one multiplier `lambda_r` per target ratio (the model is trained on several at once), `eta =
0.05`, `rho = 10`. The penalty switches on after the first 20% of training (`rate_start_frac`), once
the reconstruction warm-up has done its work. `lambda_r` may go negative: if the model keeps too few
nodes open, the penalty pushes it to use the budget.

**Why the quadratic term (a failure found by testing).** The first version used plain dual ascent
(`rho = 0`). On a toy problem, where one parameter sets the open fraction and a "task loss" prefers
using more nodes, the multiplier wound up and the open fraction collapsed to 1% or swung between 0
and 1 at multiplier step sizes of 0.5 and 0.1 (0.02 was stable). With the augmented-Lagrangian
quadratic term at `rho = 10` it settled on the target at all three step sizes tried (0.5, 0.1,
0.02); a weaker `rho = 2` was still unstable at 0.5. The test
`test_rate_controller_converges_on_toy_problem` guards this.

## Other regularisers and logs

`lb_weight` (0.01) multiplies the load-balance loss. The training log records `kd`, `recon`, `lb`,
`frac` (open fraction), `lambda` and `rate`.

## Tests

Hard-concrete: deterministic at eval, exact zeros and ones in training, Monte Carlo agreement of the
expected L0, gradient to the gate parameters. Routing: exactly `top_k` nonzero weights for valid
segments and none for padded ones, writes only to valid nodes, fewer nodes than `top_k`, load
balance higher under collapse, gradients to router/value/keys, centroids in range. Compressors:
fixed models give `floor(N/ratio)` nodes, adaptive pools open at initialisation, closed gates shrink
but never empty a memory, nodes ordered by source position, rate and multiplier logging and
checkpointing.
